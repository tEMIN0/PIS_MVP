# Учебный обмен — MVP цифровой платформы

Учебный проект для лабораторной работы № 1 по дисциплине «Проектирование информационных систем». Реализован в соответствии с требованиями методички: бизнес-операции и работа с данными вынесены в бизнес-сервисы; пользовательский интерфейс отделён от бизнес-логики; предусмотрены валидация, обработка ошибок и защита от конфликтов конкурентного редактирования.

## Функции
- регистрация и вход пользователей, хеширование паролей;
- каталог учебных материалов, поиск и фильтр по категории;
- размещение материала для обмена, бесплатного получения или продажи;
- редактирование и удаление собственных материалов;
- запросы на покупку/обмен/получение, принятие, отклонение и завершение сделок;
- проверка обязательных полей, типов и цены;
- проверка прав доступа и бизнес-ограничений;
- SQLite, внешние ключи и транзакционные условные обновления для защиты от конфликтующих действий;
- обработка ожидаемых ошибок с понятными сообщениями.

## Запуск
Требуется Python 3.10+.

```bash
python -m venv .venv
# Windows: .venv\\Scripts\\activate
# Linux/macOS:
source .venv/bin/activate
pip install -r requirements.txt
python app.py
```
Откройте http://127.0.0.1:5000. База `platform.db` создаётся автоматически.

## Архитектура
- `templates/`, `static/` — клиентский интерфейс.
- `app.py` — маршрутизация и координация запросов.
- `services/user_service.py` — бизнес-сервис пользователей и его операции с данными.
- `services/material_service.py` — бизнес-сервис материалов.
- `services/deal_service.py` — бизнес-сервис сделок.
- `database.py` — подключение и схема базы данных.
- `services/errors.py` — типизированная ошибка бизнес-уровня.

Каждый бизнес-сервис получает подключение к данным и содержит бизнес-операции. Элементы интерфейса в бизнес-сервисах отсутствуют.

## Сценарий демонстрации MVP
1. Зарегистрировать пользователя А.
2. Войти и разместить материал в категории «Математика», указать тип «Продажа» или «Обмен».
3. Зарегистрировать пользователя Б в другом браузере/сеансе.
4. Найти материал в каталоге и отправить запрос.
5. Войти пользователем А, открыть «Мои запросы» и принять запрос.
6. Завершить сделку; материал станет недоступен для новых запросов.

## Ограничения MVP
Оплата не проводится внутри приложения: тип «Продажа» фиксирует цену и позволяет отправить запрос, но платёжный шлюз не интегрирован. Файлы не загружаются на сервер — используется внешняя ссылка. Перед публичным развёртыванием нужно задать секретный ключ через `SECRET_KEY`, добавить CSRF-защиту, HTTPS, миграции БД, тесты и политику обработки пользовательских файлов.
